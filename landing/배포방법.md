# 다운로드 페이지 배포

페이지(약 600KB)와 설치파일(dmg 95MB)은 **올리는 곳을 나누는 게 맞습니다.**

| | 어디에 | 왜 |
|---|---|---|
| 페이지 (`landing/`) | Vercel | 정적 사이트에 최적, 무료, 링크 예쁨 |
| 설치파일 (`.dmg` / `.exe`) | GitHub Releases 또는 사내 드라이브 | 바이너리 배포용, 용량 제한 넉넉(2GB) |

> ⚠️ dmg 를 Vercel 에 올리는 건 피하세요. 정적 파일 한도 100MB 에 아슬아슬하고,
> 바이너리 호스팅 용도가 아니라 대역폭도 빠르게 소진됩니다.

---

## 1단계 — 설치파일 올리기

### GitHub Releases (추천, 무료)

1. GitHub 에 저장소 생성 (private 로 해도 됩니다)
2. 우측 **Releases → Draft a new release**
3. 태그 `v0.1.0` 입력 → `dist/Moreng-0.1.0-arm64.dmg` 를 드래그해서 첨부
4. **Publish release**
5. 첨부된 파일 우클릭 → **링크 주소 복사**
   (형태: `https://github.com/{계정}/{저장소}/releases/download/v0.1.0/Moreng-0.1.0-arm64.dmg`)

> private 저장소면 링크에 접근하려면 로그인이 필요해요. 사내 배포엔 오히려 이게 안전합니다.

### 사내 드라이브 (Google Drive 등)

업로드 후 **직접 다운로드 링크**를 받아야 해요. 구글 드라이브는 미리보기 링크가 기본이라
다운로드가 바로 안 될 수 있으니, 공유 링크의 파일 ID 를 아래 형태로 바꿔 쓰세요:

```
https://drive.google.com/uc?export=download&id={파일ID}
```

## 2단계 — 페이지에 링크 넣기

`landing/index.html` 맨 아래 스크립트에서 두 줄만 채우면 됩니다:

```js
var MAC_URL = "https://github.com/.../Moreng-0.1.0-arm64.dmg";
var WIN_URL = "https://github.com/.../Moreng Setup 0.1.0.exe";
```

윈도우 빌드를 아직 안 했다면 `WIN_URL` 은 `"#"` 로 두세요.
(맥에서 열면 맥 버튼만 크게 보이므로 당장은 문제없어요)

---

## 3단계 — 페이지 배포

터미널에서 **`landing` 폴더 안에서** 실행하세요:

```bash
cd ~/Documents/Claude/Projects/원티드랩/wanted-calendar-widget/landing
npx vercel
```

- 처음 실행하면 로그인 절차가 나와요 (브라우저로 인증)
- 프로젝트 이름 물으면 엔터로 기본값 사용
- 끝나면 `https://{프로젝트명}.vercel.app` 주소가 출력됩니다

정식 주소로 굳히려면:

```bash
npx vercel --prod
```

이후 페이지를 고쳤을 땐 같은 명령을 다시 실행하면 갱신됩니다.

## 사내 전용으로 막고 싶다면

Vercel 대시보드 → 프로젝트 → **Settings → Deployment Protection** 에서
**Vercel Authentication** 을 켜면 로그인한 팀원만 접근할 수 있어요.

---

## 새 버전을 낼 때

1. `package.json` 의 `version` 을 올림 (예: `0.2.0`)
2. `npm run dist:mac`
3. GitHub Releases 에 새 태그로 파일 첨부
4. `landing/index.html` 의 URL 을 새 버전으로 수정
5. `npx vercel --prod`
